# Layout：直接遍历与 query 对照

目前 `literal_parts` 已由相邻 `template_tags` 的边界推导，而不是从文本节点读取：

- 起点为前一个标签的 `end_byte`，终点为后一个标签的 `start_byte`。
- 文件首尾使用 `0` 和源文件的字节长度。
- 按前一个标签的右 trim、后一个标签的左 trim 收缩 ASCII 空白。
- 空文本仍保留，供哨兵记录执行情况和合并候选位置。

基准比较标签边界的收集方式，不会在运行时修改生产实现。

## 方法

`tests/tag_collection_benchmark.lua` 在内存中创建两个 `source_map.lua` 副本，只替换其中一个的
标签收集器。当前 query 只捕获真实的 `{{`、`{{-` token，再找到对应的兄弟闭分隔符；
两版都直接返回完整标签范围，不解析字符串里的伪分隔符。不能直接拿 `if_action` 等
节点的整个范围当标签，因为它包含分支正文。

两版使用相同的脏区缓存、字节偏移更新、标签合并、trim 和布局导出逻辑。query 提前
编译，并按行列限制局部查询；字节到行列的转换二分查询 buffer 行偏移索引，不扫描
整个源文本前缀。

先进行了 1643 次生产/query 结果对照，复用 703 组增量测试，涵盖 trim、空文本、
嵌套控制块、增删改、Unicode、临时语法错误、undo/redo。然后预热，交替测量两版，
取 11 批次的单次平均耗时中位数。GC 不关闭，批次开始前先回收。

## 历史分隔符版本的一次本机结果

单位为毫秒，不代表跨机器性能保证。完整布局包含字符串解析；局部更新包含 buffer
修改、读取文本、增量解析和布局导出。不包含 chezmoi 进程、diff 或 UI。

| 场景 | 直接遍历 | query |
| --- | ---: | ---: |
| 400 if / 19.6KB，仅收集，树已解析 | 0.751 | 1.021 |
| 400 if，完整布局 | 1.539 | 1.835 |
| 400 if，局部等长文本修改 | 0.395 | 0.423 |
| 400 if，局部文本增删 | 0.401 | 0.444 |
| 400 if，局部标签变化 | 0.406 | 0.519 |
| 1600 if / 78.4KB，完整布局 | 5.988 | 7.019 |
| 1600 if，局部等长文本修改 | 1.639 | 1.695 |
| 105KB、以普通文本为主，局部修改 | 0.165 | 0.174 |
| 400 行内嵌套块 / 23.6KB，局部修改 | 5.466 | 5.503 |

本次样例未发现 query 更快：100/400/1600 if 的完整布局约慢 17–23%，局部更新约慢 3–31%；
大段普通文本和长行样例差距较小。现有遍历本来就跳过普通文本，并二分定位局部变化，
query 没有消除布局导出和缓存维护，还增加了 capture 迭代等成本。因此暂不替换。

## 完整标签缓存对照（2026-10-20）

生产实现改为遍历时找到兄弟开闭分隔符，直接缓存完整标签，跳过表达式内部节点。
普通表达式没有单独的 tag 节点，控制节点又包含正文，因此仍需定位兄弟分隔符；
但不再保存两份分隔符记录，也不再在导出时统一配对。局部扫描先扩展到旧缓存的完整
标签；新标签范围由 parser 的语法变化范围覆盖。导出标签仍为新对象，避免修改旧 trace。

`source_map.lua` 从 550 行减少到 536 行。缓存条目通常减半；标签收集器稍复杂，
但删除了导出阶段的配对状态和错误分支。不是整个增量缓存算法的重写。

修改前保留模块快照，与修改后在同一进程中交替测量，预热后取 11 批次中位数；
包括正常分配/GC，批次间主动 GC。两版先完成 1643 次结果对照，另做 21648 次
新旧实现/随机编辑对照，涵盖标签内部编辑、控制块、trim、注释、伪分隔符和错误恢复。

单位为毫秒；本机样例，不代表跨机器保证。完整解析含字符串 parser、缓存处理和导出，
局部更新另含 buffer 修改及读取；不包含 chezmoi 进程、diff 或 UI。

| 场景 | 分隔符缓存 | 标签缓存 | 变化 |
| --- | ---: | ---: | ---: |
| 100 if / 4.9KB，完整解析 | 0.338 | 0.347 | 慢约 3% |
| 400 if / 19.6KB，完整解析 | 1.570 | 1.452 | 快约 8% |
| 400 if，局部等长文本修改 | 0.474 | 0.390 | 快约 18% |
| 400 if，局部文本增删 | 0.492 | 0.389 | 快约 21% |
| 400 if，局部插入/删除标签 | 0.563 | 0.395 | 快约 30% |
| 1600 if / 78.4KB，完整解析 | 5.948 | 6.354 | 慢约 7% |
| 1600 if，局部等长文本修改 | 1.993 | 1.640 | 快约 18% |
| 105KB 主要为普通文本，局部等长修改 | 0.166 | 0.167 | 基本不变 |
| 400 行内嵌套块 / 23.6KB，局部等长修改 | 5.338 | 5.309 | 基本不变 |

收益主要来自局部更新时处理的缓存条目减少，以及不再重新配对全部分隔符；只测收集器
并没有更快，100–1600 if 样例反而慢约 7–10%。因此保留这次改动的理由是中间结构
减少、导出逻辑简化和标签密集场景的局部更新收益，并不声称所有解析都更快。

## 复现

```sh
env XDG_STATE_HOME=/tmp nvim --headless -n -i NONE -u tests/minimal_init.lua \
  -c 'lua local ok, err = pcall(dofile, "tests/tag_collection_benchmark.lua"); if not ok then print(err); vim.cmd("cquit 1") end' \
  +qa!
```
